# M1 — Project Model, Storage Placement, Media Coverage, Analysis Modes

## Goal

Make analysis correct and robust for real-world folders: any storage location, any of the v1 cameras, photos, any length, and every analysis mode.

## Scope

- **Storage placement policy** (`ARCHITECTURE.md §4`):
  - detection on macOS and Linux
  - split and external modes, and the artifact store
  - DB snapshots via the backup API
  - cloud-placeholder detection with a download prompt
  - read-only folders
- **Project lifecycle:** open, reopen, relink moved files by fingerprint, detect new, missing and changed files, and project lease locks with read-only open.
- **Camera profiles:** `insta360` (flat, single-lens, LRV; raw 360 as `analysis_only`), `nikon` (video, N-Log hint, NEF embedded preview), `dji` (chapters, SRT telemetry), plus the unsupported-reason catalog.
- **Photos:** HEIC, JPEG, NEF and DNG ingest; Live Photo pairing; burst grouping; photo + video moment clustering; photos in mosaics and vision.
- **Clock correction:** per-device offset suggestion and storage (the UI comes in M2; the CLI can set offsets).
- **Color:** a per-profile color hint. LUT application for log sources, with the user-supplied LUT path stored per device profile.
- **Analysis modes:** L0–L3 per `ANALYSIS_MODES.md`, Quick/Balanced/Thorough/Custom, progressive deepening scoped to a project, day or selection, estimates, and cost ceilings with pause.
- **Hierarchical summaries** (shot → day → trip) and the `trip_context` table. The CLI can import context from JSON or free text. Changing context re-runs summaries only.
- **Hybrid search** (SigLIP + FTS5 with RRF) exposed over API and CLI.
- **Hardware capability probe** and a benchmark that feeds estimates.
- **Worker pool with resource classes** and per-provider rate limits.
- **Scale:** streaming and pagination everywhere, tested on the 40-hour synthetic project.

## Out of scope

- UI (M2), Tauri (M3) and edit wizard features beyond the M0 CLI.
- Music.

## Acceptance tests

1. A project on an SMB share and a project in an iCloud Drive folder both open with placement `split`. No SQLite file is ever opened read-write on those paths (asserted by an instrumented DB layer). Snapshots appear in the folder after each checkpoint.
2. A read-only folder opens with placement `external` and full functionality.
3. Moving a trip folder to another disk and reopening relinks every file with no re-analysis.
4. A real-footage fixture for each camera classifies as expected (`full`, `analysis_only` or `unsupported` with reason). GoPro and DJI chapters form single Assets, and Live Photos pair.
5. Going Quick → Thorough on one day re-uses all L0/L1 artifacts. The number of new AI calls equals the L3 candidate count for that day.
6. The 40-hour synthetic project completes L0/L1 with bounded memory (peak RSS limit set in the test) and a UI-API list page response under 300 ms.
7. The cost ceiling pauses AI tasks and resumes after the user raises it.

## Gate

No human gate. When acceptance passes and `docs/reports/M1.md` is written, continue directly to M2.
