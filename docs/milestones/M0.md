# M0 — Walking Skeleton (services + CLI)

## Goal

Produce a watchable edit from a real trip folder, end to end, using the real service boundaries. This proves the product before any UI or packaging work. Everything built here is kept, not thrown away.

The owner's decisions on the planning pass are in `docs/decisions/0002-m0-planning-decisions.md`. They are binding. Work autonomously per `docs/AGENT_WORKFLOW.md`.

## Scope

**Foundation**
- Repo scaffold per `ARCHITECTURE.md §2`, with uv, ruff, mypy (strict on `core/` and `media/`), pytest, a GitHub Actions workflow, `make check`, `make ci`, `make acceptance` and `make eval`, `LICENSES.md` and `.gitignore`. Keep the owner's existing `.gitignore` entries (`Samples/`, `Other/`).
- **`core/time.py`:** SourceTime/TimelineTime types, rational conversions, Hypothesis property tests.
- **FFmpeg tooling:**
  - LGPL build script for dev (zimg, VideoToolbox, libopenh264)
  - BtbN LGPL builds in CI
  - capability and license probe that refuses GPL builds unless `allow_gpl_ffmpeg=true`
  - typed builders in `media/ffmpeg/`
- **Synthetic corpus generator** (`mosaic-dev gen-corpus`). It produces every `EVALUATION.md §1` case plus full-range 8-bit and 10-bit HEVC 59.94, and burns a frame-index barcode into each frame. Per ADR 0004, the HEIC Live Photo pair and the 40-hour project are generated from M1, and on Linux CI the 10-bit HEVC case uses a committed fixture produced by the same generator.

**Storage and jobs**
- **Control DB** in the app-data dir, with its own Alembic tree: installation, user, project_registry, job DAG tables, and the edit-ID → project index.
- **Project DB** with its own Alembic tree.
- **Placement classifier** for all classes. Only `local` is accepted; every other class is refused with a clear message.
- **Descriptor** at `<root>/.mosaic-project.json`; everything else lives under `<root>/MosAic/`.
- **Artifact store, provenance and key hashing.** Raw probe JSON is stored as an artifact blob.
- **Job runner:**
  - DAG, scheduler, leases and heartbeat, cancel
  - one worker process, separate from the API, with a thread per resource-class slot
  - all dispatch through `Executor`
  - idempotent skip-if-artifact-exists and resume after `kill -9`

**Media (L0/L1)**
- ffprobe.
- Camera profiles `iphone`, `gopro` and `generic`:
  - chapter grouping with the logical-time map
  - LRF association and validation (proxy use only in Quick mode, which is M1)
  - GPMF gyro via an in-house KLV parser if it fits; otherwise optical-flow shake
- Unsupported reasons. Photo assets are recorded as `deferred`.
- Proxies at 720p CFR H.264 SDR, with:
  - HLG/PQ tone mapping
  - rotation
  - color-range handling
  - VFR→CFR conversion
  - a proxy→source tick map
- Adaptive shot detection (PySceneDetect's algorithm on numpy, ADR 0008), samples with pHash and embedding dedupe, sharpness/exposure/shake metrics, segments with `usable_range`, and labelled mosaics with sidecars.

**Audio**
- VAD, then faster-whisper (medium; small in CI) with word timestamps converted to ticks.
- Loudness stats.
- Speech test fixture from public-domain LibriVox or CC-BY LibriSpeech audio.

**AI**
- Provider interface and registry, with an Anthropic adapter, **Claude Code CLI and Codex CLI adapters** that use the installed apps and the owner's sign-in instead of a key (ADR 0014), and a **fake/replay adapter**. The provider for each capability is a setting (ADR 0003); `mosaic config ai use <provider>` applies a preset.
- **App configuration (ADR 0003):** `provider_profile`, `secret_ref` and `user_preferences` in the control DB; keys in the OS keyring via `keyring`; the `mosaic config` CLI (`show`, `ai set`, `ai set-key` with hidden prompt or stdin only, `ai test`, `set eval.corpus_dir`).
- Vision prompt v1, story planner v1, shot selector v1.
- Pydantic validation: retry once, then fail the task.
- Cost recording and per-run budget enforcement (`AGENT_WORKFLOW.md §4`).
- Models are settings. Defaults when the provider is Anthropic: Haiku 4.5 for vision; Sonnet 5.5 for planner and selector.

**Embeddings**
- Local SigLIP (base in prod, smallest available in CI), sqlite-vec, and embedding-only similarity groups.

**Editing**
- Retrieval, then planner, selector, **solver**, **cut refiner** (word boundaries, motion settle, usable_range), deterministic critic, and finally an immutable edit version with its JSON export.
- Planner and selector outputs are cached by key; `--variant N` forces a fresh take.

**Render**
- Chunk renderer with conform (nearest-frame), tone mapping, pillarbox for portrait sources, and silence fill.
- Assembler with two-pass loudnorm to −14 LUFS and ≤ −1 dBTP.
- Encoder order: VideoToolbox → NVENC → openh264. FFV1 lossless for frame-exact tests.
- Preview renders from proxies; final renders from originals at 1080p SDR.

**Defaults**
- 1080p output.
- Timeline rate = the dominant source rate by duration, with a `--fps` override.
- Balanced pace, stored in frames.
- `render` uses the latest version unless `--version` is given.

**CLI**

```text
mosaic init <folder>
mosaic analyze <folder> [--mode balanced]            # M0 accepts balanced only
mosaic edit <folder> --duration 180 --story cinematic_journey --chronology mostly [--instructions "..."] [--fps 29.97] [--variant N]
mosaic render <folder> [<edit_id>] [--version N] [--final]
mosaic report <folder> <edit_id>                     # selection/rejection report + metrics
mosaic-dev gen-corpus <dir> | mosaic-dev inspect <folder>
```

**API**
- FastAPI exposing the same services, with JSON endpoints and SSE.
- Paths and payloads follow `docs/ui/API_MAP.md`, including `GET /edits/{eid}/report`.
- Binds to 127.0.0.1 only and has no auth, but every request still calls `authz.check`.

**Evaluation**
- `tests/evaluation/expectations.template.yaml`, plus a **draft** `expectations.yaml` for each corpus trip, generated from the analysis and marked `draft: true`.
- A rubric template.
- `make eval` against the corpus folder in the `eval.corpus_dir` setting, using the configured provider. If anything is missing, stop at G1 with the exact `mosaic config` commands.

## Out of scope

- Storage placement other than `local`.
- Insta360, Nikon and DJI profiles.
- Photos in edits.
- Trip context, music, the AI critic, UI, Tauri, auth, Docker, OTIO.
- Quick and Thorough analysis modes.

## Acceptance tests

1. **Synthetic corpus, end to end.** Every synthetic case (VFR, rotated, HLG, PQ, start_time / edit list, chapters, no-audio, multi-audio, 120 fps, full-range 8-bit, 10-bit HEVC 59.94, corrupt) passes through analyze → edit → render using the fake AI adapter. The corrupt file is listed as unsupported with a reason. In the final render, barcodes decoded from each event match the EDL source ranges within ±1 frame (nearest-PTS for VFR).
2. **Resume after kill.** Killing the worker with `kill -9` mid-analysis and restarting completes without redoing finished tasks, as checked from the task log.
3. **Real trips.** `make eval` produces a **3-minute Airshow** edit and a **75-second Dubai** edit with the configured real AI provider.
   - The blocking zero-target metrics are all 0: duration within tolerance, mid-word cuts, dialogue truncations, adjacent jump cuts, and REJECT shots used.
   - Must-include and must-exclude are reported against the draft expectations but do not block.
   - Total real-AI spend stays within budget.
4. **No float seconds.** A schema test proves there are no float time values in the DB or the edit JSON.
5. **No repeat AI calls.** Re-running `mosaic edit` with identical inputs makes **zero** AI calls of any kind, verified by a provenance/cache test.
6. **Licenses.** `LICENSES.md` lists every dependency, model and test fixture with its license. The FFmpeg probe reports an LGPL build in CI and in the dev setup.
7. **App configuration.** With nothing configured, `mosaic config show` and `make eval` give a clear "not configured" message, never a crash. After `mosaic config ai set-key`, the key is found in no file, DB row, log or process argv. Changing a capability's provider or model changes the adapter used and the cache key.
8. **CI parity.** `make ci` passes locally, and the GitHub Actions workflow runs the same targets.

## Deliverables and gate

- Code, tests and CI.
- `tests/evaluation/results/M0/` containing metrics, cost, and the rendered edit paths.
- ADRs from 0004 onward for any deviations (0003 is an owner decision).
- `docs/reports/M0.md`.
- `docs/decisions/0001-m0-findings.md`: the weakest quality areas observed, and the recommended focus for M1–M4.
- **Gate G6:** stop here. The owner watches both edits, scores the rubric, and confirms or edits the draft `expectations.yaml` files. Then M1 starts.
