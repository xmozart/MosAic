# M2 — Web UI and Server Deployment

## Goal

The whole pipeline is usable from a browser against a Docker server, with the library/review experience that makes the app pleasant.

## Scope

All screens follow `docs/ui/`. The screens in this milestone are listed with "M2" in the `docs/ui/README.md` screen index: S0, S2–S12, S13/S14 basic, S17 player and report, S20–S23, S25.

- **Design foundation (first):**
  - tokens generated from `docs/ui/tokens.json`
  - Tailwind and shadcn mapping
  - bundled Geist fonts
  - dark and light themes
  - every `docs/ui/COMPONENTS.md` component used by M2 screens, each with a Storybook story per listed state
- **Frontend:**
  - Home
  - Inventory, including the clock-offset confirmation screen, unsupported and cloud-only lists, and placement display
  - Trip context (form, paste-and-parse, skip)
  - Analysis setup with mode cards and estimates
  - Analysis progress over SSE, with pause, resume, cancel and retry
  - Library/Review workspace: virtualized grid, hover-scrub from proxies, filters, hybrid search, detail panel, ratings, USE/MAYBE/REJECT, always/never include, notes and tags
  - Settings, including AI provider keys and media roots for the admin
- **Video playback:** proxies served with HTTP range requests.
- **Config hierarchy:** all five scopes, showing effective values with their source and Reset.
- **Server auth:** single admin (Argon2, secure cookie, CSRF), plus server-side folder browser limited to media roots with path-safety tests.
- **Secrets:**
  - server backends: env, Docker secrets, and an encrypted file with a master key
  - write-only key entry, last-4 display, and validate-key action
- **Docker:** multi-arch image, LGPL FFmpeg, compose examples (plain; NVIDIA optional), healthcheck, and a volume layout doc.
- **Edit creation (basic):** duration, destination, story preset, chronology and custom instructions, calling the M0 editing pipeline. Includes a preview player and a selection/rejection report view.

## Out of scope

- Storyboard editing, the full wizard, the AI critic UI (M4).
- Tauri (M3).
- Multi-user.

## Acceptance tests

1. A fresh `docker compose up` with one media root reaches a first rendered preview edit from the browser without any CLI use.
2. Path traversal, symlink-escape and absolute-path requests are rejected (API tests).
3. API keys never appear in API responses, logs, the project folder, the DB or browser storage. An automated scan runs over all of these after an end-to-end test.
4. A 5,000-item library grid scrolls smoothly (virtualized, ≤ 60 DOM tiles), and filter changes return in under 300 ms.
5. The UI works at 1280 px wide and above. Keyboard navigation works in the review grid per `docs/ui/screens/S10-library.md`.
6. Every M2 screen exists in both themes. A side-by-side review against `docs/ui/reference/` shows no structural deviations, or the deviations have ADRs.
7. Every state listed in the M2 screen specs has a Storybook story. Visual regression snapshots are taken for both themes.
8. The AI-vs-you rule: an automated component test asserts that AI-set and user-set disposition chips render as different variants (outlined vs. filled + user badge).
9. The endpoints in `docs/ui/API_MAP.md` used by M2 screens exist with OpenAPI schemas, and the frontend uses a client generated from them.

## Gate

**G6.** Stop when acceptance passes and `docs/reports/M2.md` is written. The owner runs `docker compose up`, tries the web UI on a real trip, and returns feedback. Bundle any M2 open questions into the same stop.
