## Try it

```bash
make desktop-bundle        # builds MosAic.app and the DMG, then checks them
open desktop/src-tauri/target/release/bundle/dmg/MosAic_0.0.1_aarch64.dmg
```

Or run it straight from the repository with `make desktop-dev`. The first launch shows S1:
1. welcome;
2. Hybrid or Local only, with your Anthropic key (stored in Keychain);
3. the on-device model downloads.

Then open a trip folder with the native picker. Closing the window keeps MosAic working from the menu bar. ⌘Q quits.

An unsigned DMG copied to another Mac is quarantined. Open it the first time with right-click → Open, or run `xattr -dr com.apple.quarantine /Applications/MosAic.app`.

## What was built

- **Desktop API access** (ADR 0057):
  - The shell starts the backend with a random per-launch token, sent on stdin and never on a command line.
  - The UI and the API share one loopback origin. The page trades the token once for an HttpOnly session cookie, and every request needs that cookie with `Sec-Fetch-Site: same-origin`, or the token.
  - Host is loopback only, and no CORS headers are sent.
  - Verified in the real WKWebView: ranged video, images and the event stream all pass.
- **Local models** (ADR 0058):
  - A pinned catalog (revision, size, SHA-256) of the Whisper and SigLIP weights.
  - Resumable HTTP Range downloads, verified before install.
  - Downloads run as app-level jobs, with byte progress, and resume after a quit.
- **S1 First run** (ADR 0059): Hybrid or Local only, the provider's key, the provider's preset for every cloud task, model downloads with paused and Retry states, and continue while downloading.
- **The shell** (ADR 0060), Tauri 2 in `desktop/`:
  - The backend runs as a sidecar, with a stdin lifeline so it never outlives the shell.
  - Health wait; the window locked to the backend's origin.
  - A crash restart that gets a new token, port and window.
  - A graceful quit: windows close, the server cuts streams after 5 s, and workers get 30 s to finish or checkpoint.
  - Menu bar Pause, Resume and Quit; a battery saver (half the worker slots on battery); the native folder picker.
  - Not sandboxed (hardened runtime; reasons in the ADR).
- **The bundle** (ADR 0061):
  - macOS 14 or later, Apple silicon.
  - python-build-standalone 3.12.15 with the locked runtime dependencies.
  - A self-contained LGPL FFmpeg 8.1.2 (static zimg, VideoToolbox) that links only macOS.
  - MosAic.app is 466 MB; the DMG is 160 MB.
  - A CI workflow builds on Apple silicon, and signs and notarizes when the secrets exist.
  - The updater sits behind an off-by-default feature.

## Problems found and fixed

- **Jobs from the browser never ran** (found at the end of M2, fixed in M2.11a). The server now supervises its workers.
- **Two requests opening one project at the same moment broke** (M3.4). Alembic's migration context is process-global; migrations now take a process lock. Found by the real app's first page load.
- **A quit could leave a worker running after the app closed** (M3.4 review). The window's event stream kept the server from shutting down. Streams are now cut after 5 s, the windows close first, and the worker ends its own child processes.
- **A dying shell left an orphaned backend** (M3.4). The backend now watches its stdin, the lifeline.
- **Replacing the window for a restarted backend quit the app** (M3.4). Closing the last window no longer quits; only ⌘Q, Quit or a signal does.
- **The app wrote bytecode into itself at run time** (M3.5 review), which would break a signed bundle's seal. Bytecode is now compiled at build time, and Python runs with `-B`.
- **Python wheels carried Homebrew search paths** (M3.5 review). A Mac with Homebrew could have loaded a library from there instead of from the app. Those paths are stripped, and the check now resolves every load.
- **The S14 estimate took 7.4 s on long trips** (M2.11a) and now takes 1.3 s.
- **S7 could save the trip details from before a parse merge** (M3.6, found from a red GitHub run). The save now carries exactly what is on screen.
- **The scale test measured pytest's memory on Linux, not the worker's** (found from a red GitHub run; ADR 0063). On Linux, a forked child's `ru_maxrss` keeps its parent's peak. The worker's own peak is about 0.5 GB on GitHub's runners, as on macOS. The test now reads `VmHWM`. The malloc-arena cap from ADR 0062 made no difference and is removed.

## Known gaps and follow-ups

- **GitHub CI was red since M2.8d** (ADR 0062), with three causes:
  - a Linux lockfile mismatch, fixed in M2.10;
  - a save race in S7, fixed in M3.6;
  - the scale test's memory reading on Linux, which included pytest's own peak. M3.6 blamed malloc arenas; ADR 0063 has the real cause and the fix.

  The local runs were green throughout. From now on a step is done only when its GitHub runs are green.

- **G1 (below).** Signing, notarization and the hardened-runtime entitlements are untested until your Developer ID is in CI. Whether ONNX Runtime or CTranslate2 also need `allow-jit` under a real signature shows only then.
- **A second clean Mac.** The checks run on a Mac with developer tools. `env -i` clears the environment, not the disk. Copy the DMG to a Mac without Homebrew or Python, open it, and analyze a trip. If anything fails, `~/Library/Logs/com.mosaic.desktop/backend.log` says why.
- **⌘Q** goes through MosAic's own menu item (the same graceful path the tests and the quit Apple Event take). The keystroke itself couldn't be scripted here: macOS blocks synthetic keystrokes.
- **S22 has no local-models section yet.** Thorough's `large-v3` downloads on first use, through the adapter.
- **Intel Macs and Windows** are not supported (ADR 0061; Windows is a later milestone).
- **Smaller items** are in `docs/STATUS.md`.
