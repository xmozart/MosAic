- **Date:** 2026-10-09

## Try it (G6)

```bash
openssl rand -base64 48 > master_key.txt              # encrypts API keys typed in Settings
MOSAIC_MEDIA=/path/to/your/trips docker compose up -d --build
```

Then open <http://localhost:8765>, set the admin password, and pick a trip folder under `/media`. `docs/deploy/DOCKER.md` covers the volumes, settings, TLS and NVIDIA.

- **The first analysis downloads the models** (over 1 GB) into the `mosaic-data` volume. On this connection that took about 20 minutes, once.
- **AI.** Add your Anthropic key in **Settings → AI providers** (it is written once and never shown again), or set **Privacy → Local only**. Analysis without a provider runs the local stages only.
- **Your folders.** On Docker Desktop, a trip folder from your Mac counts as a network share, so its live database stays in `/data` (`split` placement). The footage is never changed. Next to it MosAic writes a `MosAic/` folder and `.mosaic-project.json`. Mount the folder `:ro` to keep even those in `/data`.
- **A trip already made on the desktop** with its database in the folder moves to split the first time the server opens it. The screen says "Moving this trip's data…". The move is one-way (ADR 0055).

## What was built

- **Design foundation** (ADRs 0032, 0033):
  - tokens generated from `docs/ui/tokens.json`;
  - Tailwind and shadcn mapping;
  - bundled Geist fonts;
  - dark and light themes, with a mandatory AI-vs-you rule (outlined AI chips, filled user chips with a badge);
  - every M2 component with a Storybook story per state.
- **Server** (ADRs 0034–0036):
  - single-admin sign-in (Argon2, `Secure` + `SameSite=Strict` cookies, CSRF, lockouts, security headers);
  - media roots with a server folder browser and path confinement;
  - secret backends: environment, Docker secrets, and an encrypted file with a master key. Keys are write-only, show their last 4, and can be validated.
- **Media** (ADR 0037): proxies, frames and filmstrips over range requests; a waveform stage; the Player.
- **Screens.** Each screen built from components and tokens:
  - S0 shell: rail, header, ⌘K palette, activity, dialogs, read-only mode, the moving-data state;
  - S2 sign-in;
  - S3 Home and S4 Open folder (ADRs 0038, 0039);
  - S5 Inventory, S6 Clock check, S7 Trip context (0040);
  - S8 Analysis setup, S9 progress over SSE with pause, resume, cancel and retry, and S25 Deepen (0041);
  - S10 Library (virtualized grid, hover-scrub, filters, density, day scrubber, keyboard model, bulk bar), S11 Clip detail, S12 hybrid search (0042–0045);
  - S13 Edits and the basic S14 wizard: length, shape, story, chronology, custom instructions (0046–0048);
  - S17 preview player with the selection and rejection report (0049);
  - S20 Exports (0050);
  - S21 Project settings, S22 App settings with all five config scopes, their source and Reset, and S23 Diagnostics with a redacted bundle (0051–0054).
- **Docker** (ADR 0055):
  - multi-arch image (amd64 and arm64) with a pinned BtbN LGPL FFmpeg, refused if it reports GPL;
  - runs as non-root, with a healthcheck;
  - `compose.yaml` passes the master key as a Docker secret; `compose.nvidia.yaml` adds NVIDIA;
  - volume layout doc, `make docker` (smoke test) and `make docker-e2e`.
- **Acceptance suite and fixes found by it** (ADR 0056): see below.

## Problems found by the acceptance work (fixed)

- **Jobs created from the browser never ran** (M2.11a).
  - Nothing started a job worker for the server: the CLI starts one for the job it follows, and every test runs jobs on an in-process worker. Only the real `docker compose up` run showed the scan job waiting forever.
  - The server now supervises workers. It starts one whenever a job is pending or running and no worker is alive, and backs off when a worker dies or hangs. Workers still exit after 20 s idle.
- **The S14 estimate took 7.4 s on a 40-hour trip** (budget 2 s; the wizard asks after every pause in typing). Collecting each segment's quality metrics compared every segment with every metric of its clip. The metrics are now indexed by time: 1.3 s. Analysis and edit generation use the same code and gain too. A test checks the result against the old scan.
- **An in-folder trip opened from the browser copied its whole cache inside the request** (M2.10 review). It now moves in a `project.move` job, and the UI waits on it (invariant 8).
- **Screenshots taken on macOS would fail on Linux CI.** They are now rendered in a pinned container on every host.
- **Smaller fixes:**
  - the API map listed DELETE on the media-roots collection, not on one root;
  - screens used the mockups' raw radii, now replaced by tokens;
  - the S10 preliminary banner lacked "View progress";
  - S20 polled every loaded page while rendering.
